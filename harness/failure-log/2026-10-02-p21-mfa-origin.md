# Failure — Post-MFA resolver changed the browser origin

Classification: security  
Status: resolved  
Repeatable: yes  
Date: 2026-10-02  
PR/commit related: current change — feat/p21-p0-foundation-closure

## Symptom

The first HTTP continuation implementation redirected a 127.0.0.1 browser to localhost, losing host-bound auth cookies. Admin, Teacher and multi-role login returned to login after successful MFA.

## Evidence

Focused Playwright before-fix output reported localhost/login after starting from 127.0.0.1/mfa. The corrected four-test run is preserved in focused-browser.log.

## Root cause

The internal request URL hostname did not match the browser hostname; the client tried RSC navigation to an HTTP route.

## Responsible layer

Auth continuation response and post-MFA navigation.

## Immediate fix

Return a relative Location header after resolving current server roles. Navigate with window.location.replace after MFA so cookies and authorization are re-read through an HTTP request.

## Permanent protection

Real MFA/browser tests use 127.0.0.1 and require Teacher, Admin and multi-role destinations while preserving staff AAL2.

## Test/eval created

`tests/e2e/workspace-entry.spec.ts`, `tests/e2e/cohorts-booking.spec.ts`, existing Teacher/Admin MFA regression suites.

## Reproduction

Verify real TOTP on the isolated 127.0.0.1 server then follow auth continuation.

## Before/after proof

Before: localhost/login and RSC fetch failures observed during focused execution.

After: four focused browser tests passed in 54.1 seconds without timeout relaxation.
